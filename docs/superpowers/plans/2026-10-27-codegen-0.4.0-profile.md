# codegen 0.4.0 profile and targets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The generator detects a project profile (app type, Next, React, styling, primitives, cn, zod, table, srcDir), accepts overrides, refuses unsupported combinations, and picks template variants from it. The existing generators are upgraded to the matrix.

**Architecture:**
- **Profile module:** a new `lib/profile.mjs` builds `{ dims, flags }` from installed versions and repo files, then merges `.codegen/config.json` and `--profile` overrides.
- **Planning:** `plan()` exposes the profile to templates, evaluates object-form `when` and `supports` (generator- and option-level), and lets `out` and `requires` depend on the profile.
- **Templates:** new variants are separate template files selected by `when`.
- **Token check:** `check-tokens` reads the same profile to choose Tailwind rules or CSS-in-JS rules.

**Tech Stack:** Node ≥ 20 ESM, `node:test`, no dependencies.

**Spec:** `docs/superpowers/specs/2026-10-27-codegen-profile-targets-design.md`

## Global Constraints

- Zero npm dependencies. All output is JSON. Exit code 1 on error.
- **Dimension values (exact strings):**
  - `app`: `next-app|next-pages|react-spa`
  - `next`: `13|14|15|16`
  - `react`: `18|19`
  - `styling`: `tailwind-3|tailwind-4|styled-components|emotion|plain`
  - `primitives`: `radix|base|none`
  - `cn`: an import path or `none`
  - `zod`: `3|4`
  - `table`: `8|9`
  - `srcDir`: `true|false`
- **Detected versions outside the matrix** keep their real value (e.g. `react: "17"`) with `supported: false`. A generator whose `supports` lists that dimension refuses with `<dim> <value> is not supported (supported: …). Set it in .codegen/config.json if detection is wrong.`
- **No signal** → the newest value (`react` `19`, `next` `16`, `zod` `4`, `table` `9`), with `source: "default"`.
- **An unparseable signal** → `unknown`, which is never in any `supports` list.
- **Precedence:** `--profile k=v,…` > `.codegen/config.json` `{ "profile": {…} }` > detection. Sources: `flag|config|detected|default`.
- **Every JSON output carries `profile`:** each dim maps to `{ value, source }` (plus `supported: false` where applicable).
- **0.3.0 output must not change** for a React 19 + Tailwind 4 + Radix repo, except the server action (`(prevState, formData)`).
- Pack names stay `react` and `next`.
- Release: `VERSION` 0.4.0. CHANGELOG lists the breaking changes from the spec. The eval fixture `next` moves to `^16`.

## Review Focus

1. **Monorepo with hoisted `node_modules`** (the version is only installed in a parent folder): detection should find it by walking up. → Task 1 test.
2. **`package.json` ranges that aren't versions** (`catalog:`, `workspace:*`, `latest`): read `node_modules`. If the package isn't installed, the value is `unknown` and dependent generators refuse instead of guessing. → Task 1 test.
3. **`components.json` with a legacy `new-york`/`default` style, or no `style` key:** `radix`. A malformed file is treated like no file (`none`). → Task 1 test.
4. **Typos in `--profile` or `config.json`** (unknown key or value): an error listing the allowed keys or values, never ignored. → Task 2 test.
5. **A repo with both Tailwind and styled-components** (mid-migration): Tailwind wins, the output shows it, and `--profile styling=styled-components` switches. → Task 1 and Task 5 tests.

- [ ] **Step 4: Implement `profile.mjs`**

**Detection rules:**
- **`app`:** if `next` is a dep, it's `next-app` when `app/` or `src/app` exists, else `next-pages` when `pages/` or `src/pages` exists, else `next-app`. Otherwise `react-spa`.
- **`styling` order:** `tailwindcss` major (3 → `tailwind-3`, ≥ 4 → `tailwind-4`, < 3 → value as-is, unsupported); then `styled-components`; then `@emotion/react|@emotion/styled`; then `plain`.
- **`primitives`:** from `components.json` `style`:
  - `base-*` → `base`
  - `aria-*` → `aria` (unsupported)
  - anything else, including a missing `style` key → `radix`
  - no `components.json`, or a broken one → `none`
- **`cn`:** first match of `import\s*\{\s*cn\s*\}\s*from\s*['"]([^'"]+)['"]` in `<ui dir>/*.tsx`, sorted. The ui dir comes from `aliases.ui` via `resolveAliasDir`, defaulting to `components/ui`. Then `detectCn` from `detect.mjs`. Then `none`.
- **`srcDir`:** whether `src/` is a directory.
- **Majors:**
  - react: < 18 → unsupported.
  - next: < 13 → unsupported; ≥ 16 → `16`.
  - zod: `3.x` → `3`, including 3.25.
  - table: < 8 → unsupported; ≥ 9 → `9`.

**Interfaces:**
- Consumes: `detectProfile` (Task 1).
- Produces: `resolveProfile(root, flagString?: string) -> { dims, flags }`. It applies `.codegen/config.json` and then the flag. It throws `CodegenError` naming the bad key or value and listing the allowed ones, and on unknown top-level config keys.
- Produces: `matches(condition, ctx) -> boolean`. A string means a truthy ctx key. An object maps each dimension to a value or an array of values, all of which must match `ctx.profile`. Exported from `actions.mjs` and used for `files[].when`, `actions[].when`, `supports`, option `supports`, `out` and object `requires`.
- Produces: `plan` takes `options.profile` (the raw flag string) and returns `{ files, skipped, todo, profile }`.
- Produces: the ctx gains:
  - `profile` (dim → value)
  - `profileIs` (dim → { value: boolean } for every listed value)
  - `mui` (boolean)
- Produces: generator `supports` and option `supports` (`{ dim: value[] }`). When they fail: `CodegenError('<pack>/<generator> does not support <dim> <value> (supported: a, b).', { profile })`, or for an option, `'--<opt> is not supported with <dim> <value> (supported: …).'` A dimension marked `supported: false` fails every `supports` that lists that dimension, with the message from Global Constraints.
- Produces: `out` may be `[{ "when": {…}, "out": "pages" }, …]`, where the first match wins and a string still works. An option's `requires` entry may be `{ "package": "a|b", "when": {…} }`.
- Produces: the CLI.
  - `--detect` prints `{ ok: true, profile }`.
  - `--profile` is added to `GLOBAL_OPTIONS`.
  - Every success or error JSON includes `profile` once a root is known; an error before resolution omits it.
