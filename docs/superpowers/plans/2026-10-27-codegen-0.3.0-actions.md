# codegen 0.3.0 actions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generators describe their work as plop-style actions (`add`, `addMany`, `modify`, `append`, `custom`), templates gain helpers and partials, and every run stays all-or-nothing.

**Architecture:** `plan()` becomes async. It builds the context as today, loads helpers, then runs the actions in order against an in-memory view of the files. The result is a list of changes (`create` or `modify`) plus the skipped actions. `write()` applies the changes and rolls back on any failure, restoring modified files. The template engine gets helper calls and partials through an optional `env` argument, so existing callers keep working.

**Tech Stack:** Node ≥ 20 ESM, `node:test`, no dependencies.

**Spec:** `docs/superpowers/specs/2026-10-27-codegen-actions-design.md`

## Global Constraints

- Zero npm dependencies. Node ≥ 20 (`engines` in `package.json`).
- CLI output is always JSON. Exit code 1 on error with `{ ok: false, error, ...details }`.
- Nothing is written outside the repo root. Nothing is written at all if any action fails.
- `files` in `pack.json` stays valid (each entry = an `add`, run before `actions`).
- JSX object literals (`style={{ color: 'red' }}`) render unchanged.
- Action fields: `type`, `when?`, `path`, `template` (file) or `text` (inline, exactly one), `skipIfExists?` (add/addMany), `pattern?`, `unique?` (default `true`), `separator?` (default `"\n"`), `skipIfMissing?` (modify/append), `templates` (addMany dir), `module` (custom).
- Built-in helpers: `pascal`, `camel`, `kebab`, `snake`, `constant`, `lower`, `upper`. Precedence: repo `.codegen/helpers.mjs` > owning pack's `packs/<pack>/helpers.mjs` > built-in.
- Partials: `{{> name}}` → `packs/<owner>/templates/_partials/<name>.tpl`. `{{> @react/name}}` borrows. Repo override at `.codegen/templates/<owner>/_partials/<name>.tpl`.
- Paths: out-relative by default. A leading `/` is root-relative, and when the path has ≥ 2 segments its first directory goes through `resolveOut`.
- Release: `VERSION` 0.3.0. CHANGELOG notes the breaking change: dry-run `files` → `created`.

## Review Focus

1. **Replacement-pattern `$` in templates.** TS template literals (`` `${x}` ``) and a literal `$&` in `append` text must be inserted as written. Only `modify` interprets `$&`/`$1`. → Task 3 tests.
2. **Invalid regex in `pattern`.** A pack author's typo must give a `CodegenError` naming the action, not a stack trace. → Task 3 test.
3. **Target file without a trailing newline, or with CRLF.** An end-of-file append must not glue two statements onto one line. → Task 3 test.
4. **A conflicting `add` in the same run as a `modify`.** The modify must not be written. → Task 5 test.
5. **`custom` returning `../` or a path outside the root.** It must be refused like any other path. → Task 4 test.
