# codegen 0.2.0 — design

Agreed in a grilling session on 2026-10-12. This is the source of truth for the 0.2.0 plan.

## Goal

Frontend developers (and their AI agents) produce React/Next code that follows one team standard. The skill's generator writes the boilerplate; humans and agents write only the real logic.

## Decisions

1. **Ownership: one opinionated standard** owned by the frontend team. `.codegen/templates/` overrides stay, for genuine exceptions only (legacy repos, client-imposed rules).
2. **Stack baseline:** TypeScript + Tailwind v4 + shadcn/ui. Other styling systems are not supported (overrides only). `cn()` is auto-detected (shadcn `components.json` alias first, then `lib/utils` exporting `cn`); `--cn` remains as an explicit override.
3. **Tests are optional:** `--with-test` stays opt-in; runner auto-detected (Vitest or Jest).
4. **Component shapes as flags** on the `component` / `client-component` generators:
   - `--element <tag>` — **required**, from an allowlist: `div, span, section, article, aside, nav, header, footer, main, ul, ol, li, button, a, form, label, p, h1, h2, h3, h4, h5, h6`. Props type follows the element. Per-element a11y affordances: `type="button"` default for `button`, required `href` for `a`, a `TODO(codegen)` a11y note where the element needs one (e.g. `nav` needs `aria-label`, `div`/`span` should not be interactive).
   - `--variants` — `cva` with `variant` + `size` (both `default` to start), `VariantProps`, exported `<name>Variants`.
   - `--as-child` — Radix `Slot` (`@radix-ui/react-slot` or the unified `radix-ui` package).
   - Compound components: **dropped**.
5. **New `form-field` generator** (react and next): always a client component in Next; react-hook-form + zod (schema lives in the form), built on the shadcn `components/ui/form` primitives; `--control input|textarea|select|checkbox` (required).
6. **Missing requirements are errors.** If a flag/generator needs a package (`class-variance-authority`, Radix Slot, `react-hook-form`) or a shadcn primitive (`ui/form`, `ui/input`, …) that the repo lacks: `ok: false` with `missing`, `missingUi` and an `install` command; nothing is written. The agent asks the user before installing.
7. **Scope:** react + next packs only. vue / liquid / vanilla / aspnet stay on the roadmap.
8. **Distribution:** copy the folder (as today). Keep `VERSION` + `CHANGELOG.md` authoritative so an npm package (`init` / `update`) can be added later.
9. **Enforcement beyond the agent:** documented `lint-staged` + GitHub Actions snippets running `check-tokens`, plus a list of recommended existing ESLint rules. No custom ESLint plugin.
10. **Agents supported:** Claude Code, Cursor, GitHub Copilot (add `.github/copilot-instructions.md`). Others best-effort via `AGENTS.md`.
11. **Behavior evals:** small harness — fixture Next app, ~6 prompts incl. a reuse trap, run via `claude -p`, manual `npm run eval` (not CI).
12. **Release:** `VERSION` 0.2.0, `CHANGELOG` entry (breaking: `--element` is now required).

## Out of scope

Other packs, compound components, ESLint plugin, npm distribution, evals in CI.
